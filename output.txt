The repo `image-builders` already exists in project `ggn-nmfs-winde-dev-1`, region `us-east4`, but isn't in Terraform's state.

```bash
terraform import google_artifact_registry_repository.image-builders \
  projects/ggn-nmfs-winde-dev-1/locations/us-east4/repositories/image-builders
```
Adjust the repository ID at the end if the actual repo name differs from `image-builders` (check with `gcloud artifacts repositories list --project=ggn-nmfs-winde-dev-1 --location=us-east4` if unsure).

**Error 2 — Image not found (this confirms your Cloud Build theory):**
```
Error waiting to create Job: ... Image 'us-east4-docker.pkg.dev/ggn-nmfs-winde-dev-1/image-builders/windows-packer-builder:latest' not found.
```
Yes — this one is exactly because Cloud Build hasn't run yet, so `windows-packer-builder:latest` doesn't exist in the repo. The Cloud Run Job resource itself gets created fine, but Cloud Run tries to validate/pull the image and fails since nothing's been pushed there.

**Recommended order of operations for this customer env:**
1. `terraform import` the existing repository (fixes error 1).
2. Run `terraform apply` again — the repo import should let the rest proceed, but the Cloud Run Job creation will *still* fail on the missing image unless you run Cloud Build first.
3. Run your Cloud Build pipeline to push `windows-packer-builder:latest` into `image-builders`.
4. Run `terraform apply` once more — now the image exists and the Job should create successfully.

If you're scripting this for repeatable customer onboarding, worth sequencing it as: **import/create repo → Cloud Build push → Cloud Run Job apply**, rather than doing it all in one `apply` — that avoids this exact race every time.
